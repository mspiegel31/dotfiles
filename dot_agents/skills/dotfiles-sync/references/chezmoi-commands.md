# Chezmoi command reference

This reference describes the installed `chezmoi` (`v2.72.0`, `chezmoi --version`) and the current official command reference. The URLs below are the primary sources. Installed help is cited where the local binary is the authority for an exact flag spelling or default.

## State model

Chezmoi has three relevant states:

- **Source state:** the managed representation in the source directory, normally `~/.local/share/chezmoi`, which is also the working copy of the dotfiles repository.
- **Target state:** the source state after chezmoi applies attributes, templates, encryption, externals, and machine data.
- **Destination state:** the files currently present in the destination directory, normally `$HOME`.

Templates make the target state machine-specific; ordinary files copy from source state verbatim. [Setup guide](https://chezmoi.io/user-guide/setup/) [Source-state attributes](https://chezmoi.io/reference/source-state-attributes/)

## Command decision table

The **Owner** column identifies the native command that should own that step. Do not add shell glue for a step already covered there.

| Need | Owner and command | Exact semantics | Hazard and safe path |
|---|---|---|---|
| Discover what chezmoi manages | `chezmoi managed [path...]` | Lists managed entries in the destination, alphabetically. With no paths it lists all managed entries. It supports JSON/YAML, tree output, source-relative paths, and entry-type filters. [Managed reference](https://chezmoi.io/reference/commands/managed/) [Installed: `chezmoi managed --help`] | Read-only inventory. `--path-style=source-relative` is useful for mapping a destination entry back to source state. |
| Discover destination files that are outside chezmoi | `chezmoi unmanaged [path...]` | Lists unmanaged files under the supplied paths, or all unmanaged files in the destination when no path is supplied. A supplied path that does not exist is an error. [Unmanaged reference](https://chezmoi.io/reference/commands/unmanaged/) [Installed: `chezmoi unmanaged --help`] | Read-only inventory. It does not add anything to source state. Review the result before adopting a directory recursively. |
| Inspect source-versus-destination changes | `chezmoi diff [target...]` | Prints the difference between target state and destination state. With no target it covers all targets. `--reverse` changes the direction; `--script-contents` is true by default. [Diff reference](https://chezmoi.io/reference/commands/diff/) [Installed: `chezmoi diff --help`] | Prefer this before `apply`. It may render templates and decrypt encrypted entries, so do not send output to logs when target content is secret. A configured `diff.command` or pager can receive source/target paths or diff output. [Encryption: age](https://chezmoi.io/user-guide/encryption/age/) [Global flags](https://chezmoi.io/reference/command-line-flags/global/) |
| See both kinds of drift | `chezmoi status` | Prints a `git status`-like two-column status. Column one compares actual destination state with the last state written by chezmoi. Column two compares actual destination state with target state and indicates what `apply` would do: space = no change, `A` = added, `D` = deleted, `M` = modified, `R` = script will run. [Status reference](https://chezmoi.io/reference/commands/status/) [Installed: `chezmoi status --help`] | Read-only, but encrypted entries may require decryption and a passphrase. Use `--exclude=encrypted` or `--exclude=scripts` when those entries are not part of the review. [Age encryption](https://chezmoi.io/user-guide/encryption/age/) [Common flags](https://chezmoi.io/reference/command-line-flags/common/) |
| Record a normal destination edit in source state | `chezmoi re-add [target...]` | Re-adds modified files in target state, preserving `encrypted_` attributes. It does not overwrite templates, ignores non-files, and recurses into directories by default. With no targets it re-adds all modified files. `--re-encrypt` explicitly re-encrypts encrypted files. [Re-add reference](https://chezmoi.io/reference/commands/re-add/) [Installed: `chezmoi re-add --help`] | Use for a **non-template** file edited in the destination. It cannot be used to replace a template with its rendered destination. `--force` is a global flag and is not the documented substitute for `re-add`'s template protection. |
| Adopt or replace one destination entry unconditionally | `chezmoi add --force target` | `add` replaces an existing source entry with the current destination state. The `--force` common flag permits this even when it would overwrite a source template. [Add reference](https://chezmoi.io/reference/commands/add/) [Installed: `chezmoi add --help`] | Use only when intentionally replacing the source representation. On a templated or secret-rendering target, this captures the rendered result and can destroy portability or put plaintext in source state. Prefer `chezmoi edit` or `chezmoi merge` for templates. |
| Add a new destination entry with chosen attributes | `chezmoi add target`, optionally `--template`, `--encrypt`, `--secrets=error`, or `--prompt` | Adds targets to source state. `--template` marks files/symlinks as templates; `--encrypt` encrypts using configured encryption; `--secrets` controls the action when an unencrypted added file contains a detected secret and defaults to `warning`; `--prompt` asks before each entry. `--autotemplate` performs greedy data substitutions and implies `--template`. [Add reference](https://chezmoi.io/reference/commands/add/) [Installed: `chezmoi add --help`] | Review an `--autotemplate` result. For secrets, use `--encrypt` or an external secret mechanism rather than adopting rendered plaintext. `--secrets=error` is a useful guard for unencrypted additions, not a replacement for encryption. |
| Apply source state to destination | `chezmoi apply [target...]` | Ensures target state in the destination, for all targets when none are supplied. If a target changed since chezmoi last wrote it, the default behavior prompts before overwriting it. `--source-path` interprets target arguments as source paths. [Apply reference](https://chezmoi.io/reference/commands/apply/) [Installed: `chezmoi apply --help`] | This is the native source-to-destination owner. Review `chezmoi diff` first. `--force` suppresses prompts and can overwrite destination edits; use `--error-on-conflict` for unattended operation when conflicts must fail instead. |
| Edit source state and immediately apply it | `chezmoi edit --apply target` | Edits source state, then applies the target after the editor exits. The `--apply` mode does not apply scripts. Encrypted files are decrypted in a private temporary directory and re-encrypted after editing; templates retain `.tmpl`. [Edit reference](https://chezmoi.io/reference/commands/edit/) [Installed: `chezmoi edit --help`] | This is the safe owner for changing a template. `chezmoi edit` without `--apply` keeps the edit in source state until a later `apply`. |
| Reconcile source and destination edits | `chezmoi merge target` | Performs a three-way merge between destination state, target state, and source state. The configured `merge.command` defaults to `vimdiff`; multiple targets invoke it sequentially. If target state cannot be computed, such as a template error or failed decryption, chezmoi falls back to a two-way merge. [Merge reference](https://chezmoi.io/reference/commands/merge/) [Installed: `chezmoi merge --help`] | Use when both source and destination changes must survive. Fix template/decryption failures before accepting a fallback two-way merge if a true three-way comparison matters. The merge tool receives paths for destination, source, and target; treat those paths as secret-bearing when applicable. |
| Reconcile every modified destination file | `chezmoi merge-all` | Runs `chezmoi merge` for each file whose actual state does not match target state. [Merge-all reference](https://chezmoi.io/reference/commands/merge-all/) [Installed: `chezmoi merge-all --help`] | Review the scope first with `status`. It can open many merge sessions sequentially and inherits the merge/decryption hazards of `merge`. |
| Pull source changes and apply them | `chezmoi update` | If `update.command` is configured, chezmoi runs it with `update.args` in the working tree. Otherwise it runs `git pull --autostash --rebase [--recurse-submodules]`, using builtin git when configured or when `git` is unavailable, then applies changes by default. `--apply=false` disables the apply step; recursive submodule updates default to true. [Update reference](https://chezmoi.io/reference/commands/update/) [Daily operations](https://chezmoi.io/user-guide/daily-operations/) [Installed: `chezmoi update --help`] | This is the native remote-to-local-source and local-source-to-destination owner. It is intentionally a pull-plus-apply operation. For review before applying, use the separate `chezmoi git -- pull --autostash --rebase`, then `chezmoi diff`, then `chezmoi apply`. |
| Pull source changes without applying them | `chezmoi git -- pull --autostash --rebase` then `chezmoi diff` | `chezmoi git` runs the supplied git arguments in the working tree, and arguments intended for git must follow `--`. The official review sequence is pull, diff, then apply. [Git reference](https://chezmoi.io/reference/commands/git/) [Daily operations](https://chezmoi.io/user-guide/daily-operations/) [Installed: `chezmoi git --help`] | `git pull` changes the source working copy. This is the explicit inspect-before-apply path; do not call it a no-write operation. |
| Commit or push source state | `chezmoi git -- add ...`, `chezmoi git -- commit ...`, `chezmoi git -- push ...` | Passes git arguments through to the source working tree. Chezmoi can also auto-commit and auto-push when configured, but auto-push implies auto-commit. [Git reference](https://chezmoi.io/reference/commands/git/) [Daily operations](https://chezmoi.io/user-guide/daily-operations/) | Inspect source state first. Never commit a rendered secret accidentally captured by `add --force`; use encrypted files or a secret manager. |
| Test or inspect rendered template output | `chezmoi execute-template ...` and `chezmoi cat target` | `execute-template` evaluates literal template arguments, or reads a template from stdin when no argument is supplied. `cat` writes target contents to stdout. [Templating guide](https://chezmoi.io/user-guide/templating/) [Cat reference](https://chezmoi.io/reference/commands/cat/) [Installed: `chezmoi execute-template --help`; `chezmoi cat --help`] | Both are output-sensitive. Never pipe rendered secret-bearing output into logs, commits, or diagnostics. Use them only with controlled output or redacted data. |

## Templates: native path and hazards

A source file ending in `.tmpl`, or any file under `.chezmoitemplates`, is parsed as a Go `text/template` with chezmoi and Sprig functions. Template data comes from `.chezmoi`, `.chezmoidata.*`, config data, and runtime helper functions. Use `chezmoi data` to inspect available data and `chezmoi execute-template` to test a fragment or whole file. [Templating guide](https://chezmoi.io/user-guide/templating/) [Installed: `chezmoi execute-template --help`]

Use this decision path:

1. **Destination file changed and is not a template:** inspect with `chezmoi status` and `chezmoi diff`, then use `chezmoi re-add target`. `re-add` preserves encrypted attributes but does not overwrite templates. [Re-add reference](https://chezmoi.io/reference/commands/re-add/) [FAQ: usage](https://chezmoi.io/user-guide/frequently-asked-questions/usage/)
2. **Destination file changed and is a template:** edit the source template with `chezmoi edit target`, or use `chezmoi merge target` when both source and destination edits matter. Do not use `re-add`; do not use `add --force` unless replacing the template with the rendered file is intentional. [FAQ: usage](https://chezmoi.io/user-guide/frequently-asked-questions/usage/) [Add reference](https://chezmoi.io/reference/commands/add/)
3. **Source template changed:** use `chezmoi diff`, then `chezmoi apply`. `chezmoi edit --apply target` combines those source-edit and apply steps, but does not apply scripts. [Apply reference](https://chezmoi.io/reference/commands/apply/) [Edit reference](https://chezmoi.io/reference/commands/edit/)
4. **Remote source changed:** use `chezmoi update` when pull-plus-apply is intended. Use the explicit `chezmoi git -- pull --autostash --rebase`, `chezmoi diff`, `chezmoi apply` sequence when review is required. [Update reference](https://chezmoi.io/reference/commands/update/) [Daily operations](https://chezmoi.io/user-guide/daily-operations/)

`--skip-secrets` skips all templates containing secrets. `--exclude=templates` or `--exclude=encrypted` filters target-state entry types on commands that support common include/exclude flags. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Common flags](https://chezmoi.io/reference/command-line-flags/common/) [Installed: `chezmoi --help`]

## Encrypted files: native path and hazards

Chezmoi stores encrypted source files in ASCII-armored form with the `encrypted_` attribute and decrypts them when needed. It supports age, git-crypt, gpg, and transcrypt. `chezmoi add --encrypt` creates an encrypted source entry; `chezmoi edit` and `chezmoi edit-encrypted` decrypt into a temporary location and re-encrypt after editing. [Encryption guide](https://chezmoi.io/user-guide/encryption/) [Edit reference](https://chezmoi.io/reference/commands/edit/) [Edit-encrypted reference](https://chezmoi.io/reference/commands/edit-encrypted/)

- Use `chezmoi re-add target` for an edited encrypted destination file when preserving its encryption attribute. Use `chezmoi re-add --re-encrypt target` only when deliberately rotating the ciphertext. [Re-add reference](https://chezmoi.io/reference/commands/re-add/)
- `chezmoi diff`, `chezmoi status`, and `chezmoi apply` may need to decrypt encrypted entries. Age passphrase encryption prompts when chezmoi needs decryption, including these commands. [Age encryption](https://chezmoi.io/user-guide/encryption/)
- `chezmoi decrypt file` writes plaintext to stdout or to the requested output file. This is an intentional plaintext operation, not a sync step. [Decrypt reference](https://chezmoi.io/reference/commands/decrypt/) [Installed: `chezmoi decrypt --help`]
- `chezmoi encrypt file` writes encrypted output to stdout or the requested output file. Use `add --encrypt` for adopting a destination file into source state so source attributes remain coherent. [Encrypt reference](https://chezmoi.io/reference/commands/encrypt/) [Add reference](https://chezmoi.io/reference/commands/add/)
- Builtin age is automatic when the external `age` command is unavailable, but builtin age does not support passphrases, symmetric encryption, or SSH keys. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Age encryption](https://chezmoi.io/user-guide/encryption/)

## Dry runs, prompts, conflicts, and exit behavior

| Control | Documented behavior | Safe use |
|---|---|---|
| `-n`, `--dry-run` | The destination directory is never modified. `-v`, `--verbose` prints approximate changes and unified diffs. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Installed: `chezmoi --help`] | Use `chezmoi apply --dry-run --verbose` as a destination preview. Because the documented guarantee covers the destination directory, use the explicit `chezmoi git -- pull --autostash --rebase`, `chezmoi diff`, `chezmoi apply` sequence when you need source-repository review separated from applying. [Update reference](https://chezmoi.io/reference/commands/update/) |
| `--force` | Makes changes without prompting. On `add`, the command-specific meaning is also “allow overwriting a source template.” [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Add reference](https://chezmoi.io/reference/commands/add/) | Do not use globally in unattended apply unless overwriting destination edits is intended. Do not use `add --force` to update a template. |
| `--interactive` | Prompts before applying each target. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Use when reviewing a broad apply interactively. |
| `--less-interactive` | Prompts for changed or pre-existing targets. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Use when new targets may be applied without a prompt but existing or changed targets require review. |
| `--error-on-conflict` | Exits with an error instead of prompting when conflicts exist. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Installed: `chezmoi --help`] | Prefer with automation that must fail closed. Pair with `--dry-run` for a no-destination-write preflight. |
| `--keep-going` | Continues as far as possible after an error. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Use only when partial progress is acceptable; inspect the command's errors before treating the run as successful. |
| `--no-tty` | Does not attempt to get a TTY for prompts; prompts are read from stdin instead. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Set explicitly for controlled non-TTY invocations. It does not make a prompt non-interactive. |
| `--init` | Regenerates and reloads the config from its template before computing target state. [Common flags](https://chezmoi.io/reference/command-line-flags/common/) | Include it only when the config template must be refreshed as part of the operation. |
| `--include` / `--exclude` | Filters target-state entry types such as `files`, `scripts`, `encrypted`, `templates`, and `externals`. [Common flags](https://chezmoi.io/reference/command-line-flags/common/) | Exclude `scripts` for a content-only review and `encrypted` when keys are unavailable or encrypted files are intentionally out of scope. |
| `--refresh-externals` | `always` re-downloads externals, `auto` observes refresh periods, and `never` uses cached content unless none exists. The default without the flag is `auto`. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Avoid `always` in a routine preview unless external refresh is part of the change being reviewed. |

## Scripts and the glue-code boundary

Scripts are native chezmoi behavior, not a reason to wrap `apply` in a second synchronizer. Files prefixed `run_` execute on every `apply`; `run_onchange_` scripts execute after their rendered content changes; `run_once_` scripts execute once per unique rendered content. Scripts run in alphabetical order, and `before_` or `after_` attributes position them around destination updates. Scripts need a shebang or executable binary, but the source file itself need not have the executable bit. Empty or whitespace-only rendered scripts are skipped. Dry-run mode does not execute scripts. [Scripts guide](https://chezmoi.io/user-guide/use-scripts-to-perform-actions/) [Source-state attributes](https://chezmoi.io/reference/source-state-attributes/)

`chezmoi diff` prints script contents by default; `chezmoi status` reports scripts that will run with `R`. Configure `diff.exclude = ["scripts"]` and `status.exclude = ["scripts"]` when those outputs should omit scripts. [Scripts guide](https://chezmoi.io/user-guide/use-scripts-to-perform-actions/) [Diff reference](https://chezmoi.io/reference/commands/diff/) [Status reference](https://chezmoi.io/reference/commands/status/)

Use native scripts only for genuinely imperative work that templates and file attributes cannot express, such as installing packages, reloading a service, importing configuration into another program, or unpacking a large external. Chezmoi explicitly says scripts break the declarative approach and should be used sparingly, and its external-file guide recommends a `run_onchange_` script instead of an external for large files or archives. [Scripts guide](https://chezmoi.io/user-guide/use-scripts-to-perform-actions/) [Include files from elsewhere](https://chezmoi.io/user-guide/include-files-from-elsewhere/)

A custom `update.command` plus `update.args` is justified only when the repository's pull operation is not the documented `git pull --autostash --rebase`; otherwise `chezmoi update` already owns pull and apply. [Update reference](https://chezmoi.io/reference/commands/update/)

## Commands that can expose or mishandle templated secrets

The following are recommendations derived from the documented command semantics. They are not additional chezmoi guarantees.

| Command or mode | Documented fact | Recommendation |
|---|---|---|
| `chezmoi add --force target` | `add --force` can overwrite a source template with current destination state. [Add reference](https://chezmoi.io/reference/commands/add/) | Treat as unsafe for a rendered secret. It can replace the template with the rendered value. Use `edit`, `merge`, or encrypted source state instead. |
| `chezmoi cat target` | `cat` writes target contents to stdout. [Cat reference](https://chezmoi.io/reference/commands/cat/) | Treat stdout as sensitive when the target renders a secret. Do not capture it in logs or CI artifacts. |
| `chezmoi execute-template ...` | `execute-template` evaluates templates and writes the result to stdout. [Templating guide](https://chezmoi.io/user-guide/templating/) [Installed: `chezmoi execute-template --help`] | Use only with controlled input and output. It is a renderer, not a redaction boundary. |
| `chezmoi decrypt file` | `decrypt` writes decrypted output to stdout or `--output`. [Decrypt reference](https://chezmoi.io/reference/commands/decrypt/) | Use only when plaintext output is explicitly required, and direct it to a protected destination. Never commit its output. |
| `chezmoi diff`, `apply --verbose`, or global `--verbose` | `diff` compares target and destination; verbose mode prints unified diffs. [Diff reference](https://chezmoi.io/reference/commands/diff/) [Global flags](https://chezmoi.io/reference/command-line-flags/global/) | Keep output out of logs when rendered target content can contain secrets. Use `--exclude=encrypted`, `--exclude=templates`, or a narrower target when appropriate. |
| `chezmoi merge` | The merge command invokes a configured tool with destination, source, and target paths; target state may be rendered or decrypted. [Merge reference](https://chezmoi.io/reference/commands/merge/) [Encryption guide](https://chezmoi.io/user-guide/encryption/) | Treat the merge tool and its temporary files as sensitive. Resolve key/template failures before using a fallback two-way merge. |
| `chezmoi diff` or `chezmoi status` with passphrase-encrypted entries | Age documentation says passphrases are requested when chezmoi needs decryption, including `diff` and `status`. [Age encryption](https://chezmoi.io/user-guide/encryption/age/) | Do not assume these checks are non-interactive or key-free. Supply the required key/passphrase or exclude encrypted entries deliberately. |
| `chezmoi apply --force` | Global `--force` makes changes without prompting; `apply` otherwise prompts when a destination target changed. [Global flags](https://chezmoi.io/reference/command-line-flags/global/) [Apply reference](https://chezmoi.io/reference/commands/apply/) | Use `--error-on-conflict` instead when automation must not silently replace local edits. |

### Native ownership summary

- Destination edit to source, regular file: `re-add`.
- Destination edit to source, template: `edit` or `merge`; never routine `re-add`.
- New destination entry: `add`, with `--template` or `--encrypt` chosen at adoption time.
- Source to destination: `apply`.
- Remote source to local source and destination: `update`.
- Remote source to local source for review: `chezmoi git -- pull`, then `diff`, then `apply`.
- Source and destination edits together: `merge` or `merge-all`.
- Imperative side effect left after those native paths: an idempotent `run_`, `run_onchange_`, or `run_once_` script.

The normal sync path therefore needs no wrapper transformation layer. Glue belongs at the boundary where a file change must trigger an external imperative action, not where chezmoi already renders, encrypts, merges, pulls, or applies state. [Scripts guide](https://chezmoi.io/user-guide/use-scripts-to-perform-actions/) [Update reference](https://chezmoi.io/reference/commands/update/)
